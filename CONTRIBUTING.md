# Contributing

This project welcomes contributions and suggestions. All contributions are subject to Microsoft's [Contributor License Agreement (CLA)](https://cla.opensource.microsoft.com/), which confirms that you have the right to grant Microsoft the rights to use your contribution.

Follow the instructions from the CLA check on your pull request and complete any required signature before your contribution can be accepted. You only need to sign once across repositories that use Microsoft's CLA.

## Code of conduct

This project has adopted the [Microsoft Open Source Code of Conduct](https://opensource.microsoft.com/codeofconduct/). For more information, see the [Code of Conduct FAQ](https://opensource.microsoft.com/codeofconduct/faq/) or contact [opencode@microsoft.com](mailto:opencode@microsoft.com) with any additional questions or comments.

## Report an issue

For documentation corrections or suggestions, search [existing issues](https://github.com/responsibleai/Agent-Safety-Policy-in-A365/issues) before [opening an issue](https://github.com/responsibleai/Agent-Safety-Policy-in-A365/issues/new).

Include:

- The article section.
- What's wrong or missing, and what you expected.
- Links to supporting official documentation, when available.

Don't include credentials, customer information, or other sensitive data. Don't report security vulnerabilities through issues or pull requests. Follow the [security reporting instructions](README.md#security) instead.

## Submit a pull request

1. Search [existing pull requests](https://github.com/responsibleai/Agent-Safety-Policy-in-A365/pulls) to avoid duplicating effort. For larger changes, open an issue to discuss the proposal first.
1. Create a branch for your changes. If you don't have write access and can't fork the repository, open an issue to coordinate with the maintainers.
1. Make focused changes that follow the [Microsoft Writing Style Guide](https://learn.microsoft.com/style-guide/welcome/) and the style of the existing article.
1. Preview the Markdown you change, including [blogpost.md](blogpost.md) and [README.md](README.md), and check links and screenshots in [images/](images/). Use meaningful alt text, keep image links relative, and remove sensitive information from screenshots.
1. Commit your changes with a descriptive message and push your branch.
1. Open a pull request against `main`. Describe what changed and why, and link any related issue.
1. Complete any CLA requirements and respond to reviewer feedback.

This documentation-only repository doesn't require a build. Preview the Markdown and verify changed links and images before submitting your pull request.
